# Эрозия через NodeForge: три исполняемых прототипа

Проверено в Blender 5.2.0 LTS, NodeForge 0.65.1 dev и nodeforge.math 2.2. Ноды действительно созданы компилятором аддона и исполняются Geometry Nodes. Python генерирует текст DSL, запускает компиляцию и проверяет результат; Python не подменяет расчёт эрозии в итоговой сцене.

`erosion_models.blend` содержит четыре одинаково освещённых участка: исходный, hydraulic, D8 и MFD. Исходники `.nf` встроены в Text Editor. Для просмотра сохранённой сцены аддон не требуется. Чтобы заново компилировать исходники, нужен аддон с пакетом math. У всех моделей одинаковые начальная поверхность, сетка 96×96 и размер 10×10. Гидравлические и геоморфологические шаги имеют разный смысл; числа шагов не являются сопоставимым физическим временем.

## Что перенесено из источников

| Файл | Модель | Перенос и отличия |
|---|---|---|
| `hydraulic_grid.nf` | Сетка виртуальных труб | Напор h+w, четыре сохраняемых потока, дождь, ограничение исходящего объёма, скорость, размыв/осаждение, перенос осадка, испарение и экспорт через край. Использована схема воды из Šťava et al.; модель способности переносить осадок адаптирована, перенос выполнен консервативным upwind вместо воспроизведения всей статьи. |
| `stream_power_d8.nf` | Stream power, D8 | Выбор максимального нисходящего уклона из восьми соседей, площадь водосбора A, размыв E=K A^0.5 S. Это ограниченный явный шаг, а не неявный Fastscape. |
| `stream_power_mfd.nf` | Stream power, MFD | Сток распределяется по всем нисходящим соседям пропорционально уклону, как slope partition в Landlab. Использован взвешенный уклон; это наше расширение явного stream-power прототипа, не копия компонента Fastscape. |

Гидравлика хранит высоту h, воду w, эквивалентную толщину взвешенного материала s и четыре потока. Потоки положительны и ограничиваются доступной водой. Способность переноса C=Kc |v| |∇h| w; размыв пропорционален max(C−s,0), осаждение — max(s−C,0). Дополнительный предел размыва ограничивает локальное изменение 25% доступного перепада высот. Концентрация s/w переносится вместе с объёмным потоком воды. Единичная плотность, пористость не учитывается. Это эмпирическая графическая модель, параметры не откалиброваны в физических единицах.

Для D8/MFD площадь вычисляется повторением A_i=a+Σ p_ji A_j. D8 имеет единственного получателя; MFD — несколько. На ациклическом нисходящем графе нужен проход не короче максимального пути. Предел размыва 20% перепада препятствует пересечению высот за один шаг. Сток пересчитывается после каждого шага. Граничные высоты фиксированы; площадь каждой вершины, включая границу, равна dx² — это явно выбранная условность, отличающаяся от площади граничных ячеек в Landlab.

## Что получилось и что проверено

| Модель 96×96 | Шаги | Ноды | Изменение высоты min / max | RMS изменения | Время вычисления в этой среде |
|---|---:|---:|---:|---:|---:|
| Hydraulic | 500 | 561 | −2.9257 / +0.1063 | 0.4002 | 10.23 с |
| D8 | 24 | 611 | −0.6187 / 0 | 0.1605 | 4.96 с |
| MFD | 24 | 657 | −0.4568 / 0 | 0.1451 | 13.22 с |

Время относится только к оценке модификатора, не к компиляции или рендеру; это не переносимый бенчмарк. MFD использует 512 внутренних проходов накопления, D8 — 160.

- Все три графа скомпилировались; соединения действительны, координаты конечны. Каждый итоговый участок содержит 9216 вершин и 9025 граней.
- На закрытой сетке 16×16 за 10 шагов независимый NumPy расчёт совпал с гидравлическими нодами: максимальная ошибка высоты 1.54e−6, воды 9.51e−8, осадка 1.66e−7.
- Для гидравлики 96×96 остаток объёмного баланса материала 8.31e−5; это около 3.74e−6 от суммарного размыва. Остаток водного баланса 2.97e−7. Баланс включает оставшийся осадок, экспорт, дождь и испарение. В JSON ошибки сохранены как суммы толщин; для объёма умножить на dx².
- Площади стока сверены с независимым топологическим накоплением: D8 максимальная ошибка 3.70e−6, MFD 4.37e−6. В последнем проверенном графе пути D8 до 55 ячеек, MFD до 250. Эти проверки подтверждают накопление на сохранённом графе, а не научную достоверность формы ландшафта или сходимость всех промежуточных графов.
- При нулевом дожде гидравлика не меняет рельеф. При нулевой скорости размыва/эродируемости все модели сохраняют высоты точно.
- Грубая и тонкая сетки выполнялись, но полноценное исследование сходимости по dx и dt не проведено.

`diagnostic_maps.png` показывает реальные поля без сглаживания изображения. `models_comparison.png` — рендер фактической геометрии с одинаковыми материалом и освещением. Визуальные недостатки перечислены в `LIMITATIONS.md`.

Первый гидравлический набор параметров был отклонён: при Capacity=18, Erosion Rate=1, dt=0.04 он давал максимальную выемку около 4.6 единицы и чрезмерно разрушал холм. Его отчёт сохранён в `rejected_parameters.json`. Сохранение массы само по себе не делает такую настройку хорошей.

## Воспроизведение

Архив распаковать как папку `erosion_study` рядом с:

```
extracted/NodeForge/NodeForge/       # каталог Python аддона
upload/nodeforge.math-v2.2_nf-v0.65.1_git.zip
runtime/blender520/blender         # либо указать собственный прямой бинарник
```

Сначала полностью распаковать Blender и проверить прямой бинарник через `--background --version`. Не использовать launcher. Здесь использован официальный Blender 5.2.0 LTS; результат не выдаётся за проверку в 5.1.2.

```bash
export LD_LIBRARY_PATH="$PWD/runtime/blender520/lib"
runtime/blender520/blender --background --version
python erosion_study/build_sources.py
runtime/blender520/blender --background --python erosion_study/run_experiments.py
python erosion_study/verify_numerics.py
runtime/blender520/blender --background --python erosion_study/control_checks.py
runtime/blender520/blender --background --python erosion_study/probe_dsl.py
python erosion_study/plot_diagnostics.py
runtime/blender520/blender --background --python erosion_study/render_models.py
```

Для проверки нужны NumPy в Python Blender и NumPy/Matplotlib в системном Python. `run_experiments.py` создаёт отдельный каталог пакетов для тестов; установку пакета с разрешением Python выполнять только для доверенного присланного math. Генератор повторно создаёт `.nf`; чтобы сохранять ручные правки, менять генератор или не запускать его. Аддон не изменялся.

## Первичные источники и границы переноса

1. [Šťava et al., Interactive Terrain Modeling Using Hydraulic Erosion, 2008, полный PDF](https://www.cs.purdue.edu/cgvlab/www/resources/papers/Stava-2008-Interactive_Terrain_Modeling_Using_Hydraulic_Erosion.pdf). Взята основа водного pipe solver; многослойность, растворение, разрушение берегов и вся модель статьи не воспроизведены. Оригинал Mei et al. отдельно не проверен: ссылка на него в рассмотренной литературе не является прямой проверкой оригинала.
2. [Landlab FastscapeEroder](https://landlab.csdms.io/generated/api/landlab.components.stream_power.fastscape_stream_power.html). Взято семейство stream-power уравнений; алгоритм неявного решения Braun–Willett здесь не реализован.
3. [Landlab FlowDirectorMFD](https://landlab.csdms.io/generated/api/landlab.components.flow_director.flow_director_mfd.html). Взято slope partition по нисходящим соседям, включая диагонали.
4. [Shobe, Tucker, Barnhart, SPACE, 2017](https://gmd.copernicus.org/articles/10/4577/2017/). Изучена модель совместной эволюции скального основания и осадочного покрытия. SPACE не реализован; имеющиеся stream-power графы нельзя выдавать за SPACE.
5. [Sebastian Lague, Erosion.cs](https://github.com/SebLague/Hydraulic-Erosion/blob/master/Assets/Scripts/Erosion.cs). Изучен капельный подход; капельный алгоритм в пакет не включён.
6. [UnityTerrainErosionGPU](https://github.com/bshishov/UnityTerrainErosionGPU). Изучен другой GPU проект; это не источник гарантии корректности нашего графа.

Для дальнейшего улучшения сначала нужны контроль поворота поверхности относительно сетки, увеличение разрешения и проверка шага времени, затем менее анизотропная гидравлика и транспорт, и только после этого — многослойность/обрушение берегов. Без этих проверок назвать результат реалистичной эрозией преждевременно.
