# 42 — Color Runtime Type, Operation Capabilities and Extension API v2 (Rev. 4)

**Scope:** one `Color` feature slice of [#45](https://github.com/denikryt/NodeForge/issues/45) and [#46](https://github.com/denikryt/NodeForge/issues/46). **Inspected baseline:** NodeForge commit `3f4d2497`, internal version `0.90.3`, Blender `5.2.0 LTS`. This plan is independently implementable alongside other type features. Rev. 2 incorporated the scoped consolidation from `NodeForge-Type-System-Architecture-Review.md`; Rev. 3 reconciled explicit `type=` conversion compatibility with C06/C09, following `NodeForge-Color-Rev2-Architecture-Review.md`. Rev. 4 adds the verified Capture dynamic-item cutover fix and migrates the missing Repeat body gate, following `NodeForge-Color-Rev3-Second-Pass-Architecture-Review.md`. Baseline uses uploaded `(2)` archive (byte-identical to `(1)`; same HEAD).

## Problem / Goal

`Color` (`NodeSocketColor`) is available in Blender Geometry Nodes but absent from the canonical `NFType` enum, `.nf` type names, `node()` contracts and Python Extension API v2 annotations. As a result, a Color field cannot cross `.nf` function boundaries or a Python-backed call even though Blender supports the underlying socket. Implement one **shared Color runtime type** through the existing compiler, group, raw-node, extension and generic typed-value paths. This stage supplies type plumbing and removes duplicated type-capability tables in the operations Color joins, **not** a Color Ramp wrapper or a general library of color operations.

## Expected Behavior

`Color` is a first-class, opaque **RGBA runtime value or field**; this is a four-channel linear color, distinct from `Vector`. A `Color` output can feed a `Color` input, pass through a typed function, a runtime branch, a Repeat state, Bundle operations and a Python Extension API v2 call. Group inputs can have a four-component RGBA default. Blender computes the actual colors; NodeForge preserves type identity and valid socket links.

```python
# .nf source: a real Blender 5.2 Geometry Nodes Color output.
def color_field(factor: Float) -> Color:
    return node("ShaderNodeValToRGB", inputs={"Fac": factor}, output="Color", typ=Color)

# A reusable typed function, with an RGBA default.
def echo_color(value: Color = (1.0, 0.2, 0.1, 1.0)) -> Color:
    return value
```

```python
# Python Extension API v2: interface.py in one installed package owner.
from typing import Annotated
from NodeForge import Color, EvaluationMode

def echo_color(value: Annotated[Color, EvaluationMode.RUNTIME_ONLY]) -> Color: ...

# In the corresponding owner-local backend module:
from NodeForge.extension_api import NFType

def echo_color(context, value):
    return context.value(value.socket, NFType.COLOR)
```

The Python extension call follows **the current nested typed-function execution boundary**. Root-script direct Python backend execution remains governed by the existing runtime-capability preflight; this feature does not relax it.

## Specification

1. **C01 — One canonical identity.** `NFType.COLOR` serializes exactly as `"COLOR"`; `deserialize_nf_type("COLOR")` returns the same enum member. `.nf` recognizes `Color` in parameter and return annotations, `node(..., typ=Color)`, named `outputs={...: Color}`, and `bundle_get(..., typ=Color)`. `Color` is reserved as a type token just like `Vector`.
2. **C02 — Physical mapping and type safety.** `Color` corresponds to **ordinary, single-value** Blender `NodeSocketColor` inputs/outputs and `NodeTreeInterfaceSocketColor` group interfaces. A Color output linked to a Color input has `link.is_valid == True`. Explicit wrong-type declarations (`Color` on a Vector output, or Vector on a Color output) raise `CompileError` for raw `node(..., typ=...)` and typed interfaces. The separate `type=` overrides on Capture/Store retain their existing Blender-supported conversion semantics (C06); they are not raw `node(..., typ=...)` assertions. Existing List/Grid structure restrictions remain in #45 and are outside this slice.
3. **C03 — Typed source functions.** `Color` can appear as required/optional `.nf` input, returned output (including multi-return), source-module import and nested/shared/unique group call. Socket name, order, type and default survive **Compile Script, Update Script and Reload Function from Source** according to the current group-contract rules. For Capture Attribute nodes, linked and unlinked dynamic items also survive backup, cutover and rollback with the same item names, count, Blender data types and physical Color/Vector sockets; an unrepresentable Capture item makes the copy fail instead of silently dropping it.
4. **C04 — RGBA defaults.** A `Color` parameter default is exactly four finite numeric components `(R, G, B, A)`, normalized to binary32 in order, including alpha. Color defaults accept list/tuple in compiler-owned type-directed/default contexts; RGB triplets, bool components, non-finite values and nonnumeric data raise a precise compile error. Accept finite HDR values above `1.0`; reject negative components rather than silently accepting Blender's clamp. An omitted Color argument uses its declared RGBA default. Persist/reload all four components without truncation or mutation. No public `Color(...)` constructor is added.
5. **C05 — `node()` Color values and literals.** Raw-node `typ=Color` and named Color outputs preserve socket identity/metadata. `inputs={"Color": runtime_color}` links the physical Color socket. A raw **Color socket** accepts a compile-time RGBA tuple of four finite components as a literal default; other socket types retain their existing tuple-size rules. Raw-node regeneration and physical-ref validation preserve four components. Blender's pre-existing `NodeSocketColor` limits are honored without silently converting invalid inputs.
6. **C06 — Existing generic typed operations and their capabilities.** Pre-existing Switch, Repeat, Capture and attribute type/token capability lists have one immutable operation-specific mapping each, shared by semantic analysis and backend lowering; legacy duplicated declarations are removed, with baseline-equivalence tests before adding Color. A Color value is valid in `select()` / runtime `if` merges, `repeat_range()` carried state, `bundle()` / `bundle_get(..., typ=Color)` / `bundle_set()`, `store_named_attribute()`, `store()` (where geometry context applies), `capture_attribute()` and `sample_index()`. Exact Blender tokens are: Switch `input_type="RGBA"`, Repeat item `"RGBA"`, Bundle item `"RGBA"`, named/store/sample attribute `"FLOAT_COLOR"`, Capture item `"RGBA"`. Preserve exact Color typing through outputs. For `capture_attribute(..., type=...)`, an explicit supported Capture token selects the result type, including Blender-accepted conversions from the input field; omitted `type` infers from the input. For `store_named_attribute(..., type=...)` and `store(..., type=...)`, an explicit supported alias selects the target Blender attribute type and Blender performs its existing valid socket conversion; omitted `type` infers from the input. Existing conversions remain accepted, including `capture_attribute(geo, position().x, type="VECTOR")` (captured `Vector`; Capture item `VECTOR` / physical `NodeSocketVector` output) and `store_named_attribute(geo, "color", position().x, type="COLOR")` (Blender `FLOAT_COLOR` attribute). Invalid override tokens still raise `CompileError`; genuinely unsupported new Color combinations are validated against their operation and actual Blender sockets rather than rejected solely because source and target `NFType` differ.
7. **C07 — Extension API v2.** `from NodeForge import Color` exports an **annotation-only** marker; `MARKER_TO_NF_TYPE[Color]` is `NFType.COLOR`. `Annotated[Color, EvaluationMode.RUNTIME_ONLY]`, finite unions including Color, and `Color` return annotations normalize to the existing `TypeSpec("NF_SET", ...)`. `context.value(socket, NFType.COLOR)` accepts only current-group Color outputs and returns a typed `ExtensionBackendValue`; extension input/result checks and semantic `RuntimeRef` / compiler-owned IR retain Color. Stale, fabricated, wrong-owner, wrong-direction and mismatched-type values fail under existing contracts.
8. **C08 — Static extension Color values.** `Annotated[Color, COMPILE_TIME_ONLY]` and `Annotated[Color, COMPILE_TIME_OR_RUNTIME]` accept only detached, canonical four-component RGBA data for their compile-time branch; a Color default declared in a v2 signature uses the same validation as C04. The backend receives a detached RGBA tuple for static arguments and an `ExtensionBackendValue` for runtime arguments. Validation must distinguish a four-number Color from a three-number Vector and preserve typed tuple/list semantics of extension **structural data**. Do not reinterpret unrelated `tuple[float, ...]` or Python `list` extension fields as Colors.
9. **C09 — Compatibility and isolation.** Existing `Float`, `Int`, `Bool`, `Vector`, `Geometry`, `Material`, `Object`, `String`, `Bundle` and `Rotation` behaviors, their serialization tokens and public signatures remain unchanged. In particular, the documented explicit `type=` conversion/selection semantics of Capture/Store and the resulting valid Blender links are preserved; strict raw `node(..., typ=...)` type declarations remain strict. Color support centralizes four **operation-specific** capability maps and introduces no new global type registry, versioned schema, owner kind or Blender datablock. Capture item reconstruction failure aborts the copy/commit and uses existing backup/cutover/rollback ownership; previously valid authoritative groups and external links remain intact after failed updates. Type identity is compiler-owned `NFType.COLOR`; physical socket ownership remains the current node group; regenerated values never outlive a compilation/invocation.

## Architecture

**Canonical source type and IR.** Add `NFType.COLOR` in `nf_types.py`, `TYPE_COLOR` / `"Color"` to `semantic/constants.py::TYPE_TOKEN_NAMES`. Existing `IRValue`, runtime binding records and `blender/values.py::Value` already carry arbitrary `NFType`; extend only actual type filters/maps. `serialize_nf_type` / `deserialize_nf_type` and persisted interface metadata remain **schema compatible**: new enum token and `NodeSocketColor`, using the existing identity and `default` fields. **Precedent:** the existing `Rotation` runtime/Extension API marker split; adopt the same canonical type/physical value separation, including its annotation-only marker behavior.

**Physical group and defaults.** Register `NFType.COLOR: "NodeSocketColor"` in `blender/socket_types.py`. Update `semantic/callable_contracts.py::canonicalize_group_input_default` and `GroupInputContract` defaults set. Make `blender/interface.py::_set_socket_default` type-/socket-aware so it assigns and checks **four** RGBA components, while Vector remains three; make a Color default assignment failure fail compilation instead of silently persisting a different default. Existing `_json_safe_default`, versioned declaration metadata and root interface matching retain ordered RGBA numbers. **Precedent:** Blender [`NodeTreeInterfaceSocketColor.default_value`](https://docs.blender.org/api/main/bpy.types.NodeTreeInterfaceSocketColor.html) is a four-item floating array; Blender 5.2 runtime test confirms four components and float32 storage. `Color` attributes use linear RGBA ([Blender 5.2 attribute types](https://docs.blender.org/manual/en/5.2/modeling/geometry_nodes/attributes_reference.html)).

**Raw `node()` boundary.** Add Color to `blender/raw_nodes.py::_SUPPORTED_TYPES`, and admit RGBA tuples in `semantic/builtin_calls.py::_raw_input_literal` and `blender/raw_nodes.py` literal normalization. Enforce the **physical destination socket** `NodeSocketColor` for four-component defaults and only three-component defaults on Vector; use existing `RawPhysicalSocketRef` schema-v2 output/input identity and metadata, updating literal validation/round-trip accordingly. **Precedent:** `plans/39_raw_node_socket_addressing.md`, existing raw-node physical identifier and preflight protocol; reuse it, without adding selector changes or a new serialization schema.

**Shared operation-specific type capabilities.** Introduce `type_capabilities.py` at the `NodeForge` package root, importing only `NFType` and `types.MappingProxyType`. Define exactly four read-only `NFType → Blender enum token` mappings: `SWITCH_INPUT_TYPES`, `REPEAT_ITEM_TYPES`, `CAPTURE_ITEM_TYPES`, `ATTRIBUTE_DATA_TYPES`. Populate each from its **current** baseline support, then add Color (`"RGBA"` to Switch/Repeat/Capture and `"FLOAT_COLOR"` to attribute operations). For example:

```python
from types import MappingProxyType
from .nf_types import NFType

SWITCH_INPUT_TYPES = MappingProxyType({
    NFType.FLOAT: "FLOAT", NFType.INT: "INT", NFType.BOOL: "BOOLEAN",
    NFType.VECTOR: "VECTOR", NFType.GEOMETRY: "GEOMETRY",
    NFType.STRING: "STRING", NFType.BUNDLE: "BUNDLE",
    NFType.COLOR: "RGBA",
})
# REPEAT_ITEM_TYPES, CAPTURE_ITEM_TYPES and ATTRIBUTE_DATA_TYPES
# retain their exact existing supported entries and add Color where Blender allows it.
```

Each mapping describes **that operation's** supported types. Missing entries mean the operation does not support the type; share no universal allowlist. This is **not a global type registry**. Keep `NFType`, `TYPE_TOKEN_NAMES`, `blender/socket_types.py`, `MARKER_TO_NF_TYPE`, and IR under their current owners. These maps have no `bpy` imports, runtime registration, caches, wildcard fallbacks or persistence.

**Consumers and duplicate removal.** Replace `semantic/analysis.py::_SWITCH_TYPES`, `semantic/control_flow.py::_SWITCH_TYPES`, and the dictionary inside `blender/nodes.py::_switch` with `SWITCH_INPUT_TYPES`; retain branch condition/equality checks and diagnostics. Replace `semantic/body.py`'s early carried-state type set, `semantic/ir.py::_REPEAT_STATE_TYPES`, and `blender/ir_lowering.py::_repeat_item_type_for_nf_type`'s local table with `REPEAT_ITEM_TYPES`; retain the existing `repeat_range state ... has unsupported type ...` diagnostic, Repeat state identity and zone construction. This early body check runs before IR/backend validation; changing only IR/backend leaves Color Repeat state rejected. Replace `semantic/builtin_calls.py::_capture_result_type`'s duplicate forward/reverse tables and `blender/geometry.py::_capture_attribute_geometry`'s two dictionaries with `CAPTURE_ITEM_TYPES` plus derived inverse lookups; preserve override parsing, diagnostics and selection/domain handling. Replace `semantic/builtin_calls.py::_analyze_sample_index_operation`'s type allowlist and `blender/geometry.py::_attribute_data_type` mapping with `ATTRIBUTE_DATA_TYPES`; retain `_ALLOWED_STORE_TYPES` because it parses **user-facing aliases** rather than declaring runtime type capabilities. Semantic modules import the shared pure-Python module directly, never `blender/`.

**Transactional Capture item reconstruction.** In `blender/group_backend.py::_sync_capture_attribute_dynamic_items()`, restore each Capture item with the **constructor socket token** expected by `capture_items.new()`, rather than passing the persisted RNA `item.data_type` unchanged. The supported readback-to-constructor translation is `FLOAT → FLOAT`, `INT → INT`, `BOOLEAN → BOOLEAN`, `FLOAT_VECTOR → VECTOR` and `FLOAT_COLOR → RGBA`; `FLOAT_VECTOR` and `FLOAT_COLOR` differ from the constructor tokens in Blender 5.2. Keep this physical boundary translation local to the copy helper; the shared `CAPTURE_ITEM_TYPES` map continues to describe semantic `NFType → constructor token` capabilities. On an unrecognized persisted item type, failed `capture_items.new()` call, missing mapped Capture node, or mismatched destination item **count, name, or persisted data type**, raise `CompileError` with source node/item context. Validate every item, including those without links, **before** link restoration. `_copy_group_contents()` already calls this helper for backup, cutover and rollback; `blender/root_update.py` uses the same helper for dynamic-item restoration. Propagate failure into those existing transactional/recovery paths without adding a registry, schema, separate rollback mechanism or global link-validation abstraction. **Evidence:** Blender 5.2 verified that `capture_items.new("VECTOR", ...)` reads back `FLOAT_VECTOR` and `capture_items.new("RGBA", ...)` reads back `FLOAT_COLOR`; feeding either readback back to `.new()` fails and the current helper silently skips the item.

**Type overrides (explicit conversion contract).** Keep override parsing and operation support separate from strict raw-node type assertions. `semantic/builtin_calls.py::_capture_result_type` uses the shared `CAPTURE_ITEM_TYPES` (and a derived inverse) to select the captured semantic result type: input type when `type` is omitted, requested supported Capture token when supplied. `blender/geometry.py::_capture_attribute_geometry` uses the same token and keeps linking the original input field to Blender’s configured capture socket, including Blender-supported conversions such as `Float → Vector`. In `_analyze_store_operation` and `blender/geometry.py::_store_named_attribute`, preserve the existing `_ALLOWED_STORE_TYPES` alias parser and explicit override precedence; e.g. `type="COLOR"` maps to `FLOAT_COLOR` even when the input field is `Float`, and Blender performs the accepted conversion. For new Color paths, add `NFType.COLOR` to automatic inference and accept the Capture override token `RGBA`; when a new Color conversion creates a link, verify `link.is_valid` in the compiler-owned candidate graph and report unsupported socket combinations before publishing. Preserve existing accepted mismatched overrides without blanket source/result `NFType` equality. `ATTRIBUTE_DATA_TYPES` keeps its own native `FLOAT_COLOR` token. Add `Color: "RGBA"` directly to the already centralized `blender/bundle.py::_BUNDLE_SOCKET_TYPES` and retain its current owner; the four shared maps do not subsume Bundle logic. The Blender 5.2 executable verified each applicable physical mechanism including `capture_items.new('RGBA', 'color')`.

**Consolidation invariant.** Original operation capability tables are physically removed, leaving the four shared maps and existing Bundle table as the only declarations for their respective operations. Tests compare each operation's baseline supported types and **exact enum tokens**, including inverse Capture lookups and previously rejected types, prior to enabling Color. A new module without deleting the duplicated tables is outside this plan.

**Extension API v2.** Define `Color` alongside other annotation markers in `extension_annotations.py`, export it in `__init__.py`. The declarative signature normalizer in `extensions/interface.py` already derives runtime types from `MARKER_TO_NF_TYPE`; the backend `ExtensionBackendContext.value()` / `blender/extension_backend.py` already validates via shared `blender/socket_types.py`. For static Color arguments/defaults, extend `extensions/interface.py::_infer_detached_default_type` and `extensions/values.py::{static_nf_type, _canonical_static_nf}`, with **type-directed** Color selection and detached RGBA representation; adapt `semantic/ir.py::_detached_nf_type` and any existing static-IR validation boundary that assumes only `ConstVector`. Use a canonical detached **four-float tuple** for static Color: `extensions/values.py::static_nf_type` and `semantic/ir.py::_detached_nf_type` recognize it within `NF_SET` validation, while extension `LIST`/`TUPLE_FIXED`/`TUPLE_VAR` continue following their declared structural `TypeSpec` paths. A `ConstColor` carrier is unnecessary; keep all stored data immutable. No Python/Blender color object passes through semantic IR. **Precedent:** `docs/EXTENSION_API.md` evaluation modes and existing `ConstVector` canonical static NF path.

**Blender evidence.** Executed using Blender `5.2.0 LTS`: `ShaderNodeValToRGB` has `NodeSocketColor` output; a Geometry Node Tree supports `GeometryNodeSwitch.input_type='RGBA'`, Color Bundle and Repeat items, Color Store Named Attribute and Capture sockets. `ShaderNodeRGB` cannot be instantiated in Geometry Nodes and must not be used in tests/examples. Four-component defaults work; 3-component defaults fail, HDR above 1 survives, negative values get clamped by Blender. The semantic layer should report invalid Color defaults before publishing candidate graphs.

**Boundary and lifetime invariants.** `Color` travels between `.nf` semantic state → `IRValue` → backend `Value` → real `NodeSocketColor`; between `.nf` and Extension API via `RuntimeRef` / `ExtensionBackendValue`; and through existing group/bundle/Repeat interfaces. The owning group owns sockets; source owners/extension owners retain their current package snapshot identities; Color carriers are recreated on every compile/update. Preserve the existing capability restriction on direct root physical extension calls. **Excluded:** new types, runtime List/Grid structures, Color arithmetic, `.r/.g/.b/.a` projection, `color()` literal constructor, generalized Blender implicit type conversions, Color Ramp wrapper, dynamic Blender items redesign, and changes to #41–44.

## Implementation Steps

1. **Canonical type.** Add `NFType.COLOR`, `TYPE_COLOR`, public `.nf` token/return annotations and exact socket mapping. Prove `Color` is accepted by the existing typed IR and is rejected on non-Color sockets (C01–C03). Preserve pre-existing type token strings.
2. **RGBA defaults and raw `node()`.** Implement four-component validation once in `canonicalize_group_input_default` (numeric finite values; `>= 0`, float32 normalization, no alpha loss). Make group-interface assignment four-component and fail closed. Pass raw `node()` RGBA constants through frontend, backend and schema-v2 physical metadata; keep literal handling socket-specific. Verify generation and regeneration including wrong-size/type (C04–C05).
3. **Consolidate operation capabilities, then enable Color.** First record baseline Switch, Repeat, Capture (including token→type inverse), and attribute supported-type/token pairs; create four immutable maps in `type_capabilities.py`, migrate **every** consumer including `semantic/body.py`'s early `repeat_range` carried-state check, **delete old tables and the local Repeat set**, and run parity tests for each allowed and rejected type. Next add `NFType.COLOR` entries (`RGBA` or `FLOAT_COLOR`), extend the existing Bundle map, and verify `select`/`if`, Repeat, Bundle, `store_named_attribute`, `store`, `capture_attribute`, and `sample_index` via physical `link.is_valid` checks. Preserve pre-existing Capture/Store explicit `type=` conversions and alias parsing (C06/C09); do not add a general source/result type-equality check. Test `capture_attribute(geo, position().x, type="VECTOR")` (semantic result `Vector`, Capture token `VECTOR`, valid Blender links), `store_named_attribute(geo, "color", position().x, type="COLOR")` and geometry-context `store(..., type="COLOR")` (both `FLOAT_COLOR`, valid Blender links). For new Color cases, verify type inference, `capture_attribute(..., type="RGBA")`, and valid physical links; invalid tokens or unsupported Color-specific combinations use the operation’s own diagnostics. Replace prior Color-rejection expectations in `tests/blender/test_capture_attribute.py` with positive Color tests and invalid-token negatives. In `blender/group_backend.py::_sync_capture_attribute_dynamic_items()`, restore the exact persisted Capture item types using `FLOAT_VECTOR → VECTOR` and `FLOAT_COLOR → RGBA` when calling `.new()`; preserve existing matching tokens, validate every restored item/count/type/name, and raise `CompileError` on any missing or invalid item. This is required for existing Vector and new Color Capture nodes, independently of whether an item is linked.
4. **Extension API type bridge.** Add marker and public import, runtime `NF_SET` matching, and `context.value()` Color acceptance. Enable detached four-component Color defaults and static/mixed evaluation modes without recasting unrelated structural extension arguments; adapt only the static type-inference/storage checks requiring it (C07–C08); represent detached Color as an immutable four-float tuple. Write one local test package with `Color` input, Color result, a finite union, and a Python backend that produces a real Color socket.
5. **Integration and docs.** Test nested package extension → `.nf` typed function → raw Color consumer and a pure `.nf` producer → Python backend consumer; test Source Reload and Update Script with defaults/links and with **linked and unlinked Capture items**, including backup, cutover, failed-copy rollback and shared root-update restoration; update the five affected manual pages to document RGBA, the Extension API marker, and the existing `type=` override conversion contracts in `docs/BUILTINS.md` (Capture overrides select the captured result type; Store overrides select the Blender attribute data type; supported Blender conversions apply). Add a concise changelog entry and one minor version bump at **integration** (baseline `0.90.3` would become `0.91.0`; if parallel branches land first, base the bump on the merged version). No changes to packages/issue #47 in this stage.
