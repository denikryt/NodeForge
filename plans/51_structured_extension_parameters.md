## Problem / Goal

`nodes.capture_attribute()` currently takes positional values plus a string such as `"VECTOR:Rest Position,INT:point_index"`. `nodes.menu_switch()` uses a comma-separated string of labels. These duplicate structure already expressible by source syntax, lose exact labels containing delimiters, and require manual Capture type declarations.

Support one-level typed structured input parameters in the existing declarative Extension API. Capture keys declare item labels; each value's already-acquired NFType determines its socket type. Menu labels become a compile-time list. Preserve static socket defaults, existing compiler-owned runtime typing, the independent physical oracle, and grouped update/rollback. No general-purpose runtime dictionaries or lists, new NFTypes, evaluation modes, phases, or Nodes-specific compiler syntax. The old Nodes collection API is development-only: replace it outright, with no script compatibility or legacy group migration requirement. The core built-in `capture_attribute()` remains unchanged; only `nodes.capture_attribute()` changes. Keep `EXTENSION_API=2`, the Inspector and catalogue format unchanged. Structured parameter support is generic; node-specific adaptation belongs to the existing generator collection branches.

## Expected Behavior

```python
from packages import nodes

pos = nodes.position()
idx = nodes.index()
result = nodes.capture_attribute(
    geometry=base,
    domain="POINT",
    elements={
        "Rest Position": pos,
        "point_index": idx,
        "height": pos.z,
        "weight": 0.5,
        "selected": idx > 10,
    },
)
geo = result.geometry
rest = result["Rest Position"]
height = result.height
```

```python
options = ["Low", "Medium", "High, x"]
result = nodes.menu_switch(
    a, b, c, data_type="FLOAT", menu="Medium", elements=options,
)
value = result.output
chosen = result["High, x"]
```

The examples assume `base` and `a/b/c` are appropriate values in the enclosing `.nf` definition. Inline and `__inline__=False` have the same public behavior. Constants reach native socket defaults; runtime expressions become links. Index Switch keeps its integer `elements` and positional inputs.

## Specification

1. **SP-01 — Declaration.** A fixed parameter of an executable BACKEND_ONLY extension may declare `Annotated[dict[str, T], mode]` or `Annotated[list[T], mode]`, where `T` is an existing marker or finite marker union, and `mode` is one existing `EvaluationMode`. The mode applies to each leaf, not to a physical collection. Both positional-or-keyword and keyword-only parameters work. A callable may also have ordinary parameters and ordinary `*items`. Reject unannotated NF collections, invalid key types, nested collection declarations, `Any`, semantic records as leaves, collection-valued `*args`/`**kwargs`, and structured parameters in overloaded families or same-name semantic-body callables in this release. A `DynamicResults` resolver does not constitute a semantic body. Existing semantic RECORD/LIST contracts are unchanged. Collection results are not introduced.
2. **SP-02 — Source shape.** `dict[str,T]` accepts an explicit dictionary display at the argument site, with exact compile-time string keys and scalar expressions as values. Keys may be literal or existing compile-time string expressions; reject runtime/non-string keys, duplicate evaluated keys before dictionary construction, `**` expansion and comprehensions. Preserve source insertion order, case, whitespace and punctuation; apply existing `validate_named_result_key` (nonempty, valid UTF-8, no NUL, at most 63 bytes). `list[T]` accepts an explicit list display or a list already available through existing CTFE (e.g. `options = ["A", "B"]`). An already-CT list is admitted for CT_ONLY/mixed modes; RUNTIME_ONLY requires a list display with source leaf occurrences. Reject tuple-as-container, `*` expansion, runtime-produced container values and runtime leaf lists stored in variables. Do not add dictionary assignments, indexing/mutation, iteration, first-class callable objects or arbitrary structural value bindings to the DSL. An ordinary variable or function call *inside* a leaf is supported. Nested list/tuple syntax used as an existing Color/Vector/Rotation scalar literal is not a new nested collection.
3. **SP-03 — Leaf acquisition.** Apply existing evaluation selection, `static_nf_type`, declared-type compatibility and canonicalization independently to each leaf. CT_ONLY rejects unavailable static leaves; RUNTIME_ONLY uses existing runtime acquisition; mixed mode selects static when available, runtime only on genuine `ConstEvalUnavailable`. Hard errors propagate. Static constants remain canonical defaults; no extra constant node solely for containment. Runtime types are actual analyzed NFTypes, not inferred from source names or socket values. Use existing ambiguity diagnostics for an untyped three-component literal accepted by both Vector and Rotation; `vector(...)` CTFE produces a typed ConstVector; direct expressions, bound names, list members and aliases preserve that type across detached compile-time snapshots (AR51-01). A runtime Rotation expression remains a Rotation. No new coercion or type inference. Whole named/tuple results must first be projected to one value. Each explicit leaf is acquired at most once per actual call occurrence; repeated references reuse the existing producer; distinct calls remain distinct.
4. **SP-04 — Omission and defaults.** Empty list/dict is a real container, distinct from absent argument or `None`. Required containers without an argument fail. For CT_ONLY/mixed parameters admit plain list/dict defaults, validate every leaf and key at declaration normalization, detach and retain exact order and selected types. Reject mutable aliases crossing owner snapshots, unsupported defaults, `None` as container/leaf, and any declared default for RUNTIME_ONLY containers. Fresh public containers are built for each resolver/backend call; mutation cannot change the normalized contract, later calls or the other phase.
5. **SP-05 — Phase contract.** Dynamic resolver receives the existing outer argument mapping; structured parameter values are ordered dict/list of `ResultRuntimeArg` and `ResultStaticArg` leaves. Ordinary and variadic parameters retain their current representations. Backend receives plain dict/list of the same shape with raw canonical static values and validated `ExtensionBackendValue` runtime leaves, exactly as ordinary scalar arguments. Resolver runs once during SEMANTIC; physical implementation runs once per inline occurrence or grouped child materialization; no resolver invocation in BACKEND. Both direct and named DynamicResults and all static result forms remain available. Malformed transport, missing slots, type/provenance/ownership mismatch fail before invoking physical implementation.
6. **SP-06 — Capture Attribute.** This requirement applies to `nodes.capture_attribute()` only, not the core built-in `capture_attribute()`. Replace positional `*items` and string `elements` with keyword-only `elements: Annotated[dict[str, Bool | Color | Float | Int | Rotation | Vector], EvaluationMode.COMPILE_TIME_OR_RUNTIME] = {}` (marker union generated from catalogue, not hardcoded). Keep geometry/domain and all other existing fixed inputs/options. Each key creates exactly one capture item with that type and attaches exactly one value. No value-less item or `None` placeholder; `{}` creates no capture items and retains the base result. Output schema is existing `geometry`, `selection`, followed by exact ordered keys; conflicts with base keys fail during SEMANTIC. A Matrix or any other unsupported leaf fails. Retain existing domain support and output carrier rules. Input and output socket labels, count, types and native identities must match the requested collection, with no silent Blender renaming or normalization of keys.
7. **SP-07 — Menu Switch.** Replace `elements` string with `Annotated[list[String], EvaluationMode.COMPILE_TIME_ONLY] = ["A", "B"]` generated from `initial_names`. Retain positional values, `data_type`, `menu`, optional trailing input defaults and all supported configurations. Labels must be nonempty unique exact valid socket keys, list nonempty, selected menu must occur in list, labels cannot collide with base output key. Reject excess positional values, unsupported selected type and invalid runtime Menu values. Preserve ordered base output plus one Bool result per label, including singleton menu list. No mapping of labels to input values in this task. Index Switch contract remains unchanged.
8. **SP-08 — Group interface and update.** Only runtime leaves create child input sockets. Static leaves specialize native defaults inside child. Runtime input identity is extension occurrence + declared parameter + exact dict key / list index; dictionary reorder must not retarget an external link or override. Use readable scoped input labels (e.g. `elements[rest_position]`, `elements[0]`); labels may be shortened deterministically to fit physical socket limit, but identity and source/output keys remain exact. Existing normal/variadic input names and semantic-state `Dependency_N` unchanged. Same key/index and socket type preserve external input state on recompilation, including all supported current defaults of required structured runtime inputs (zero/empty string, numeric strings, transparent Color, sub-epsilon Float/Vector and Rotation, supported Object/Material pointers), whether linked or unlinked (AR51-02). Removed/type-changed structured inputs do not attach to unrelated sockets; new or type-changed inputs use native defaults. Successful cutover and strict rollback restore the captured values without the source-default comparison heuristic. Existing ordinary/source-group override policies remain unchanged. Named output migration retains AR-01/B, direct output `Result`. Preserve authoritative group identity, one-call reuse, full rollback, savepoint rollback, save/reopen, and resource inventory. No pointer-only snapshot restoration or positional fallback for named keys.
9. **SP-09 — Editor.** Show structured parameter leaf types and actual default displays (`dict[str, ...]`, `list[String]`, `{}`, `["A", "B"]`). Dynamic result preview and member completion use existing compiler probe; exact attribute-compatible names offered, other keys remain bracket-accessible. An unresolved or incomplete argument produces existing unresolved behavior, not speculative keys. Preserve imported aliases and bare calls, shadowing, signature selection and ordinary semantic LIST/RECORD display.
10. **SP-10 — Migration and release.** Old Capture positional/string syntax and Menu comma-string syntax are rejected; no permanent aliases or temporary adapters. Migrate all first-party callers and verifier fixtures in the same change as generated owners. No compatibility or migration is required for scripts or generated groups using the old development API. Do not implement a mapping from legacy `items_N` to dictionary keys or special handling of compiler-owned parent links. Start from freshly compiled groups using the new API. If a legacy group is nevertheless submitted to the normal update path, retain existing safety checks and atomic failure on ambiguous correspondence; this can occur even when its only user is the compiler-owned parent. No promise of recompilation or automatic upgrade of old graph instances. This is ordinary transaction safety, not a legacy compatibility feature. Release NodeForge 0.103.0 and Nodes 1.8.0 with minimum NodeForge 0.103.0; real upgrades must replace old owner files without forced removal. Keep `EXTENSION_API=2`, the Inspector and catalogue format unchanged. Coverage counts and supported native states remain unchanged; only the public form of two collection wrappers changes.
11. **SP-11 — Collection copy integrity.** Every group/root copy route (candidate publication, backup, private root transfer, equivalent-update savepoint restoration, late root failure reconstruction and full rollback) retains Capture item labels/types/defaults, Menu enum labels/order/descriptions/selection and values, and Index item count/values. Each newly copied standalone collection node has its actual layout reconstructed and verified before collection-dependent defaults or raw locator validation; rebuild links only after valid endpoints exist. Preserve surviving native nodes during late root recovery. Exact-case Capture keys such as `"Geometry"` and `"Selection"` remain distinct from lowercase base result keys; duplicate native display labels must not redirect defaults or links to fixed sockets. For non-raw exact copies, regenerated item identifiers may differ only when the independently verified ordered logical/physical layout establishes the corresponding slot. Fixed identifiers and declared raw locators retain their existing identity requirements; no name fallback for mismatched collection endpoints or change to ordinary endpoint policy. Invalid layout, default readback or link correspondence aborts atomically. This repairs inherited defects without changing Index Switch public API or introducing migration of old development graphs.

## Architecture

### A. Existing flow and scope

Confirmed C20 flow: `extensions/interface.py` accepts `Annotated[NF_SET, mode]` or frontend-semantic RECORD/LIST; `TypeSpec` already has LIST and DICT_STR for record storage. `_analyze_extension_backend_call()` binds candidates, acquires each explicit scalar once, selects overload, produces `AnalyzedCallOperand` / `AnalyzedStaticCallOperand`, calls resolver, and lowers to `IRCallArgument` / `IRStaticCallArgument`. `_bound_arguments()` reconstructs public backend arguments. `_analyze_extension_semantic_call()` instead transports compact semantic state, with invocation-owned RuntimeRefs; grouped materialization gives these dependencies `Dependency_N` labels. Capture and Menu do not need a semantic state transform. Extend the declarative path; do not promote static leaves to RuntimeRef or create generated semantic dataclasses merely to transport arguments.

The architecture reviewer inspected `nodeforge_structured_elements_prototype_evidence.zip`, its README, both diffs and logs on C19. Capture used runtime-only semantic-state transport and Menu used a static list; neither establishes the general declarative transport below. The archive itself is not mounted in the plan-amendment environment. Obtain it for implementation if available, together with the review diffs/probes; do not apply the prototypes wholesale. AR51-01/02 and the SP-11 follow-up were experimentally tested by the reviewer on C19, not C20. The exact C20 checkout is available here; its relevant source paths were inspected and retain the reported mechanisms. Reproduce on C20 before integrating. The actual source flow and catalogue were inspected; Blender label-boundary, group-copy and equivalent-update probes were run. Section D records new baseline findings. Plan 50 explicitly defers physical output-label inheritance; this remains out of scope.

### B. Declaration and acquisition (SP-01–04)

- In `extensions/contracts.py`, add a private/internal predicate distinguishing annotated one-level LIST/DICT_STR with NF_SET item from `is_frontend_semantic_type_spec`. Keep TypeSpec recursive schema/storage and result admission unchanged. Validate fixed parameter kind, mode, frozen defaults. In `extensions/interface.py:_normalize_parameter_annotation`, inspect `typing.get_origin/get_args` for list/dict inside Annotated and normalize leaf with `_normalize_nf_set`. Existing overload restriction remains; `classify_extension_execution()` rejects structured declarations with a semantic body or non-executable result before acquiring arguments. Check registry's semantic contract lookup path; do not silently select BACKEND_ONLY when a same-name body exists.
- Use existing `ResultStaticArg` to retain per-default selected NFType plus canonical immutable literal; for LIST default store ordered tuple of typed leaves, DICT_STR ordered tuple of `(key, typed leaf)` pairs. `default_type` remains reserved for direct NF_SET. Default normalizer and contract constructor validate shape, types, keys and detached leaves; `python_signature()` may carry this internal immutable default for binding, not pass it directly to owner code. Render public default from normalized storage in editor. Explicit and omitted empty container produce identical layouts.
- In `semantic/analysis.py:_analyze_extension_backend_call`, preserve ordinary candidate selection. For the admitted single structured signature, expand a bound container into ordered leaf acquisition records before normal scalar evaluation; do not call `analyze` on its entire dict/list. For dict, validate/evaluate key expressions once with CTFE, then acquire values in order. For a list literal, process each AST leaf; for an already-CT list, acquire canonical static entries once (RUNTIME_ONLY rejects a precomputed list rather than inventing source occurrences). Distinguish AST occurrence, already-acquired CT value and normalized default by provenance, not by value's Python type alone. Reuse a small local scalar acquisition/canonicalization helper with ordinary path where it avoids duplication. Ordinary overload ambiguity logic and exact/compatible ordering unchanged; no second overload engine. Contextual parsing only, no global AST Dict evaluator. Check `semantic/body.py`, residualization and editor probe for AST occurrence reachability and facts; fix only concrete traversal omissions.
- **AR51-01 — preserve typed CTFE constants.** In `semantic/compile_time.py:_seed_const_copy_memo`, replace the plain normalized tuple stored for `_is_const_vector(value)` with `ConstVector(tuple(normalize_float_constant(item) for item in value))`. `build_semantic_constant_snapshot()` uses this detachment before acquisition; erasing the carrier makes a bound Vector ambiguous against Rotation in `static_nf_type()`. Preserve the existing shared memo, aliases/cycles, foreign-object rejection and conservative branch joins. Do not reinterpret ordinary tuples or catch ambiguity as runtime unavailability. Once canonicalization produces the raw tuple, retain the selected static NFType as specified in C. The review validated the local change on C19; verify direct/bound/list/alias cases on C20 and rerun CTFE consumers.
- For mixed structured calls with several parameters, keep existing source acquisition order, then transport parameter/element order. Facts and runtime nodes correspond exactly to retained leaf operands. Build resolver container from selected typed leaves, in original order, as a fresh list/dict; build IR transport separately before invoking the resolver so resolver mutation cannot alter it.

**Precedent:** [Python 3.13 typing/Annotated](https://docs.python.org/3.13/library/typing.html#typing.Annotated) and [PEP 585](https://peps.python.org/pep-0585/) provide inspectable generic declarations; use existing annotation normalization rather than a new DSL type marker. [Python dictionary displays](https://docs.python.org/3.13/reference/expressions.html#dictionary-displays) and [data model](https://docs.python.org/3.13/reference/datamodel.html) establish ordered displays and normal duplicate overwrite behavior. NodeForge deliberately rejects duplicates at AST/acquisition boundary because they declare distinct physical slots. Existing `semantic/source_callables.py:analyze_local_return_shape()` validates exact keys before constructing named return metadata; reuse its principle, not its literal-only source return grammar.

### C. Detached call transport (SP-05)

Extend existing flat positions instead of introducing a runtime structural IR value. Add one immutable ordered `structured_arguments` field (default `()`) to `AnalyzedCall` and `IRCall`:

```python
# tuple[(parameter_index, tuple[str | int, ...]), ...]
structured_arguments = ((2, ("Rest Position", "weight")), (3, (0, 1)))
# dict parameter 2: runtime leaf at slot 0, static leaf at slot 1
# list parameter 3: two leaves; () means an explicitly empty container
```

Use existing `parameter_index` and `variadic_index` fields for flat leaf coordinates `(parameter_index, element_ordinal)`; selected parameter spec and layout distinguish a collection from true `*args`. Clarify internal field documentation (it now represents indexed element slots as well as variadic positions); do not change existing scalar/varargs wire format. Layout stores keys/indices only; type and value remain on existing operands/default path. No duplicated value trees or AST in IR. Ordinary fixed slot uses `None` ordinal as before. A layout entry for an empty collection has no operands.

`validate_extension_argument_positions()` continues to guard unique coordinates and contiguous indices across runtime/static operands; extend it to check layout ordering/unique parameter indices, exact key/index shape, valid keys and slot cardinality. Invoke from both `AnalyzedCall.__post_init__` and `IRCall.__post_init__`. Reject nonempty layout on non-extension or semantic-state calls. At selected-spec boundary also verify layout exactly matches structured parameter kinds, no layout for ordinary/vararg, indices in bounds, correct runtime/CT mode and leaves allowed by declared item spec; empty allowed only for actual container parameters. A declaration-specific check for static canonical data must respect its selected leaf type (do not re-run ambiguous `static_nf_type` on a canonical vector tuple). For structured static operands retain the selected NFType as explicit optional metadata on existing static operand records (`static_type`, default None for existing paths); validate against canonical value and declared set, never infer from canonical tuple alone. For runtime leaves validate actual operand NFType and socket provenance. Reject missing/extra operands, malformed layout and static metadata before physical invocation. Lowering copies validated layout and static type metadata; no container operations or structural results in value/SSA paths.

`blender/extension_backend.py:_bound_arguments` reconstructs list/dict from slots and layout; static raw leaves and runtime wrappers use existing conversion. Selected spec check must also run before grouped interface population, not only at invocation. Audit consumers of IRCall/static operands (dataclass replacement, fingerprint, equality, validation, body/Repeat/branch lowering), preserving scalar and source-call semantics. Fingerprint includes ordered layout and selected static leaf types in addition to existing operands; changing keys/order/static values must not produce an equivalent wrong group. No new public runtime wrapper/context API is needed.

**Ownership / lifetime:** declaration defaults belong to immutable owner snapshot; acquired source occurrences belong to current analysis; layout/leaf positions belong to one analyzed call and its detached IR; no global registry of collections. Physical wrappers belong to current candidate tree, fresh backend container dies with invocation. Group call-site authority remains existing ExtensionCallSiteId, not container identity. **Precedent:** [MLIR language reference: operations, operands and attributes](https://mlir.llvm.org/docs/LangRef/) separates SSA operands from constant operation metadata. Here layout is detached metadata and only runtime leaves enter SSA; no MLIR dependency or generic IR redesign. Local precedent is existing `IRCall.arguments/static_arguments`, semantic dependency slot validation and Plan 50 named result metadata.
