# NodeForge Nodes

Coverage reference for **Blender 5.2.0 LTS**.

The table maps Blender node names and `bpy` class identifiers to functions in the bundled `nodes` package. NodeForge installs the bundled library automatically when the extension is enabled. Import it with `from packages import nodes`. See the [Package Guide](PACKAGES.md#importing-package-callables) for general import rules. For node behavior, refer to the [Blender Geometry Nodes manual](https://docs.blender.org/manual/en/latest/modeling/geometry_nodes/index.html).

The library is generated from Blender’s Python API (`bpy`): the development Inspector probes node classes, configuration properties and socket layouts, and the generator produces bindings for supported configurations.

## Socket types

Runtime types exposed by Nodes: `Bool`, `Color`, `Float`, `Geometry`, `Int`, `Material`, `Object`, `Rotation`, `String`, `Vector`. Blender socket subtypes (for example, `FloatAngle` and `VectorEuler`) use the corresponding NodeForge runtime type.

Blender socket classes observed in the catalogue but not supported as runtime values by this library: `Bundle`, `Closure`, `Collection`, `Font`, `Image`, `IntVector3D`, `Matrix`, `Menu`, `Sound`, `Vector2D`, `VectorXYZ2D`. The core DSL also supports `Bundle` through its own [bundle operations](BUILTINS.md#bundles).

`Menu` input options exposed by a wrapper are compile-time string arguments. Runtime Menu socket links and Menu-valued results are not supported. Dynamic node item collections are a separate mechanism from `Collection` data-block sockets.

A fixed wrapper argument supplies one value to a native multi-input socket. Use the core [`join()`](BUILTINS.md#geometry) operation when joining several geometries.
